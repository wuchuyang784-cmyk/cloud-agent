# F1：固定源码 pi 镜像与受控 Runtime wrapper

用户已授权先开发 F1；Linux 服务器规格不阻塞本批。本文固定本批实现边界，不开放用户执行或部署既有运行环境。

## 目标与边界

使用 `upstreams/pi` 固定提交 `11f99114506ad2cc759cb389663edaf7546cbe8c`（coding-agent 1.1.0）的源码和锁文件构建镜像。新增独立 `runtime/pi/production/` wrapper，不复用 legacy 的可选认证、环境共享 Key、每任务重置、字符数 token 兜底和无界输入/队列。保留 legacy 回归文件；不改平台能力开关、数据库、E2 probe 或现有部署。

F1 的 HTTP 为未来 Runtime Gateway 的内部协议，不面向用户浏览器。F2 负责用户凭据与模型网关；F3 负责 Linux/gVisor/网络/存储隔离；F4 负责用户授权、配额与生命周期；F5 负责页面。F1 仅在独立临时资源中使用真实 pi + 本机测试模型协议服务验收，不使用用户 Key 或付费模型。

## 镜像与来源

- 先检查 gitlink、上游 HEAD、工作树干净、版本及锁文件哈希；不更新子模块或上游源码。
- 从固定提交 `git archive` 生成有界临时构建上下文，只包含上游已提交源码、F1 wrapper 和构建定义，不上传 `.env`、业务数据库、output 或 Git 私有配置。
- 固定基础镜像 digest，`npm ci --ignore-scripts`，显式上游离线构建；不安装发布版 pi 替代源码、不执行上游 prepare/publish。
- 上游 Git 排除了必需模型目录 JSON。仅从同版本 `pi-ai@1.1.0` 发布 tarball 提取 43 个目录 JSON（不是可执行代码），锁定 SHA-512、逐文件 SHA-256，并保留上游 `check:model-data` 校验；记录该数据发布包与主源码提交的区别。不能在每次构建时重新抓取变化中的模型列表。
- 保存源码提交、锁文件/构建定义/wrapper 哈希、实际镜像 ID 和摘要构建证据。产物使用独立 F1 标签，不覆盖 legacy/预发镜像；实际部署按 digest。
- 运行非 root，根文件系统可只读；仅工作空间、Agent 状态和有限 tmp 可写，无 Docker socket、宿主路径、原始 Provider Key 或平台数据库凭据。

## Wrapper 契约

- 显式只读机器配置，绑定 `agentId/runId/runGeneration`；runId 支持现有 039 ledger 的完整 `run-UUID` 及独立验收 UUID，不剥离前缀、不将两者当别名。运行请求独立随机签名 Secret 从文件加载；不从业务 `.env` 读取配置，不允许无认证启动。
- 模型配置为可信配置文件中的固定 Provider/模型/网关端点和短期模型 token 文件，不接收浏览器/任务的 env、argv、路径、任意模型端点或原始 Provider Key。测试配置只允许显式测试模式的回环测试模型服务。
- `/livez` 仅标记服务存活；`/readyz` 必须实际启动 pi 并以匹配 ID 的 `get_state` RPC 确认固定模型及会话可用。没有进程或初始化失败返回 503，不以 spawn 成功或固定延时当就绪。
- 受保护内部任务接口校验签名的 method、原始 path、正文、时间戳、nonce、运行身份；签名只对本运行有效，所有身份不匹配拒绝。健康端点不泄露身份或路径。
- 一个 wrapper 绑定一个持久会话文件，跨 prompt 不 `new_session`，重启恢复同一会话；多会话切换归 F5，F1 不开放任意 sessionPath 或上游 RPC 透传。
- 同时最多一个任务，忙时拒绝而不是无界排队。任务 UUID 在持久状态先占位，重复提交/进程崩溃后未知结果不得再次执行。结果未知如实报告，不自动重放付费或文件操作。
- `POST /v1/tasks` 输出有界 NDJSON：开始、文本增量、受限工具事件、结束/失败/取消；每条带任务 ID 和序号，不透传内部模型对象、工具输出/错误正文、stderr 或凭据。工具事件只提供受限元数据及成功/失败；模型文本属于用户对话内容，不承诺能识别任意机密或路径，后续 F3 必须隔离工具可访问的控制 Secret。未知或全零占位 token 为 null，pi 报告 usage 对多轮 assistant 消息求和，不作为最终账单。
- 固定取消接口只取消当前匹配任务；超时/客户端断开同样停止任务。先 abort，再等待 settled；不确认结束时终止 pi 进程并保持不可就绪，不能让后续任务与旧工具同时执行。工具子进程真正回收需容器退出/运行层策略及 F3 验收，不把 RPC abort 当作已删除容器。
- 限制正文、RPC 单行/累积输出、事件数量/字节、未完成 RPC、nonce 缓存、请求读取与执行时间；慢消费者触发有界失败而非增长内存。关闭时拒绝新任务并等待/终止当前子进程。
- 模型错误和 stderr 对外仅返回固定分类；明确禁用上游自动重试（可配置的重试上限为零），不加载工作空间扩展/Skill/项目配置。F1 不声称可防同 UID 内 pi 修改自己的数据或退出沙箱；强隔离由 F3 承担。

## 验收

1. 单元/进程协议测试先失败后实现：无认证、错误身份/代次/路径、重放、有界输入、真实 RPC 就绪、持久会话、流式事件、unknown usage、并发拒绝、取消/超时/退出、迟到响应隔离、慢消费者及输出溢出。
2. 固定源码镜像真实构建，独立临时网络/卷/凭据与测试模型 HTTP/SSE 服务；真实 pi 发起模型协议调用并执行 read/write/bash，验证文件结果、连续会话、重启恢复、取消和实际 usage。测试结束按精确归属清理。
3. 回归 legacy pi 与平台默认关闭边界；运行后端全量。业务/预发容器、原始记录、CA 与私有配置不变。
4. 中文记录分别列出成功证据和未验收边界；无真实 Provider、Linux 服务器部署、gVisor、多租户授权或用户侧上线声明。
