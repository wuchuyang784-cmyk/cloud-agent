# 统一管理与监控控制台设计

日期：2026-10-07。状态：方案二、五项导航与本详细设计已获用户确认；正在实施，尚未部署。

## 1. 目标与范围

管理员通过现有 Better Auth 登录，在同一个管理控制台使用平台概览、用户账号、Agent 服务、运行监控和告警。详细图表复用 Grafana；Prometheus、Grafana、Alertmanager、本地告警接收器继续独立运行。

用户已选择“统一登录和导航，复用 Grafana”，不再重复比较仅增加链接或全部重写图表的方案。普通客户端不增加平台管理功能，不改变个人空间授权，不开放真实 Agent 或模拟执行。

本设计在现有 E:\cloud-agent 工程落地，不迁往其他 SaaS 编程平台，不上传源码或凭据到新服务。新功能先通过隔离验收，再安排常驻预发更新；不把此前 D2 部署授权当作后续任意停机、迁移或发布授权。不自动提交、推送本轮新文件。

## 2. 已核对的现状

- `apps/admin-console/src/App.tsx` 与 `session.ts` 提供两项业务导航、Better Auth 登录和账号治理交互。
- `apps/platform-api/src/admin/routes.mjs` 每次通过 `readAdmin(..., 'me')` 验证管理角色，`store.mjs` 限制账号必须 active。
- `scripts/monitoring-config.mjs` 使用 Grafana 独立管理员 Secret，关闭匿名访问，尚未配置认证代理。
- `scripts/preprod-config.mjs` 将 `/admin/` 静态页面放在 8443，Grafana 独立代理位于回环 9443。
- 已有看板覆盖 API、副本、请求量、延迟、错误率、数据库就绪、连接池和 API 进程资源；不是宿主机全集指标或真实 Agent 心跳。
- 告警接收器保存经过白名单清洗的本地通知，尚无供管理端使用的历史查询接口。
- `scripts/preprod.mjs` 的镜像版本计算未包含管理端源码和构建输入；本批必须补齐并测试。

## 3. 控制台信息架构

保持现有紧凑业务控制台、CSS 变量和 lucide-react 图标，不重做客户端。

| 导航 | 首版交付 | 数据来源与边界 |
| --- | --- | --- |
| 平台概览（默认首页） | API 可采集副本、数据库就绪、近 5 分钟请求速率、P95、5xx 比率、当前告警摘要 | 平台后端执行固定监控查询，显示采样时间；无数据不伪造为正常 |
| 用户账号 | 现有查询、分页、账号状态、暂停/封禁/解除及治理记录 | 保留现有 Better Auth、角色与 D1 规则 |
| Agent 服务 | 现有 Agent 归属、记录状态、引擎和更新时间 | 明确标注数据库记录；不宣称实时运行，不增加启停 |
| 运行监控 | 管理端页面内嵌固定平台看板，提供时间范围、刷新和受鉴权的完整看板入口 | Grafana 渲染；不开放数据源管理、插件安装、看板编辑或任意目标代理 |
| 告警 | 当前告警列表、严重级别、状态、开始时间和允许公开的对象标识 | 固定查询 Prometheus 规则/告警；首版只读，不包含静默、规则编辑或完整通知历史 |

首版不新增全平台用户/Agent 总数：现有有界分页不能推算准确总数。告警页说明“当前告警”不等于历史通知或外部消息送达；已有本地通知文件继续保留。

## 4. 登录与权限合同

### 4.1 日常访问

复用当前平台会话，不新建另一套业务账号密码。新增 `monitoring:read` 与 `alerts:read` 权限，首版授予 active 的 `platform_viewer`、`platform_operator`、`platform_admin`；三种角色在监控端均只读。

普通用户、仅有个人空间 org_admin 的用户、被撤销平台角色者及 suspended/banned 账号均不能访问监控。账号治理仍只有 active 的 platform_admin 可写，不能操作自己或限制最后一个有效管理员。

每个监控数据请求及受保护的 Grafana 请求都由网关向平台 API 发起鉴权子请求，复核会话、账号状态和平台角色；不能仅依赖菜单隐藏、iframe 首次加载检查或 Grafana 缓存的角色。

建议 Grafana 技术身份采用 `bairui:<不可变 Principal 用户 ID>`，避免邮箱变化或与现有 `admin` 同名发生身份合并。只创建只读技术映射，不复制密码，不按邮箱自动合并，不自动授予 Grafana Server Admin。

### 4.2 认证代理

- 网关删除客户端提交的身份头，只根据平台 API 成功鉴权响应注入身份与只读角色。
- Grafana Auth Proxy 只信任网关在监控网络上的确定 IP，不信任整个 overlay 网段；网关重建时同步更新地址并验收。
- 日常链路不向 Grafana 转发 Better Auth Cookie、浏览器 Authorization 或旧 Grafana 会话；只转发必要的、已验证身份信息。
- 不给日常用户签发可绕过平台鉴权的 Grafana 登录令牌，不允许通过直连后端、旧端口或另一个代理前缀绕过平台权限。
- 匿名访问维持关闭；不把共享 Grafana 管理员密码、服务令牌或 Cookie 放进 URL、前端代码或 localStorage。
- 首版不提供长连接实时流，使用有界 HTTP 查询和定时刷新，避免已经建立的连接长期绕过撤权复核。
- 退出、封禁或撤权后拒绝后续新请求；不承诺撤回已返回的数据或强制中止已准入的在途请求。

## 5. Grafana 内嵌与应急入口

日常统一入口保留 `https://localhost:8443/admin/`，其中运行监控页面内嵌 `https://localhost:9443/d/bairui-platform/bairui-platform`。端口不同但仍属于本机同一站点；9443 网关对每个非应急请求调用 `/api/admin/monitoring/access`，只有平台鉴权成功才向 Grafana 注入只读身份。Grafana root_url 保持 9443，避免资源和跳转绕过鉴权。

内嵌只允许管理端自身 origin，通过精确的 `frame-ancestors` 控制；不能全局放开跨站嵌入。复用 Grafana 正式子路径与认证代理能力，不在浏览器中注入密码，不用匿名访问解决 iframe 登录问题。

原 Grafana 本地管理员保留为运维应急入口：`/login`、登录所需的白名单 `/public/*` 静态资源和带有效 `grafana_session` 的请求直接交给 Grafana，其余请求必须经过平台鉴权。静态资源链路清除 Cookie/Authorization 和 Set-Cookie；伪造同名会话 Cookie 只会到达 Grafana自身校验，不能获得访问。应急链路清除身份代理头、使用独立凭据，不依赖平台 API 或业务认证数据库；普通 Auth Proxy 响应剥离 Grafana Set-Cookie，避免平台用户得到可绕过后续复核的独立会话。不在普通管理导航展示应急密码，已有 Secret 不替换、不复制进前端。

**第一个实现检查点是实际兼容性验证：** 在一次性 Grafana/Caddy/假鉴权服务环境验证受保护看板、静态资源、Cookie 清理、Auth Proxy、iframe 策略、应急登录页和伪造会话共同工作。平台鉴权服务不可用时，应急登录页仍可独立加载。不能只用配置字符串单测宣布兼容。

若单实例不能同时满足两条访问链路，先报告证据和替代方案，不能静默取消应急入口、关闭鉴权或额外部署第二份 Grafana。本检查点不修改当前常驻预发。

## 6. 数据接口与状态

新增建议接口：

- `GET /api/admin/monitoring/overview`：固定的概览指标、监控启用状态、响应时间、采样时间和每项数据状态。
- `GET /api/admin/monitoring/alerts`：有界当前告警列表，只接收固定严重级别/状态过滤；不提供告警写入。
- `GET /api/admin/monitoring/access`：仅供网关鉴权子请求使用，成功时返回不可变技术身份与固定 Viewer 角色头，不返回页面数据；Grafana 每请求同步角色，防止持久技术用户被提升后继续保留高权限。

平台概览与告警 JSON 接口由 API 在内网查询固定 Prometheus 地址。浏览器不得传入上游 URL、任意 PromQL、数据源配置或访问令牌；不会把 Prometheus/Alertmanager 原始 API 全部透传出去。

接口采用固定 DTO，过滤任意标签、注释、内部链接及原始错误；详细 Grafana 看板仍仅向有平台监控权限的运维身份开放。连接与查询设覆盖排队和执行的绝对截止时间、响应字节上限、有界队列和并发上限；为监控请求保留独立并发额度，不耗尽账号管理请求容量。

HTTP 行为：未登录及 banned 沿用现有 401，无平台权限或 suspended 返回 403，依赖不可用/超时 503。所有身份相关响应 `no-store`，上游失败不返回原始 URL、SQL、Cookie 或 Secret。

数据状态区分：

- 未配置/关闭：导航仍可见，显示“监控未启用”，不尝试公网默认地址。
- 正常：展示值及有效采样时间。
- 空数据：显示“暂无采样”，不把缺失值记为 0；无有效请求窗口时延迟与错误率显示暂无数据。
- 过期：显示最后采样时间并明确标为过期，不继续标绿；概览新鲜度阈值默认 60 秒，须根据样本时间判断而非响应时间。
- 不可用：当前监控页面显示重试状态，用户账号和 Agent 服务页面仍可使用。

API 可采集副本 0 是有定义的采集结果，不等于其他无数据指标可补 0。数据库就绪只代表应用连接探针，不等于备份、磁盘、复制或全库健康。

前端默认每 30 秒刷新概览/告警，在页面隐藏时停止，恢复可见时重新检查权限；切换页面、退出、账号切换、撤权均取消旧请求、清除敏感数据，拒绝乱序响应回填。运行监控可使用既有 15 秒看板刷新，但每次查询仍经过服务端鉴权。

## 7. 工程划分

- `apps/admin-console/src/session.ts`：保留认证与权限；将账号/Agent 列表状态与监控状态解耦，监控失败不把整个管理端切到不可用。
- `apps/admin-console/src/App.tsx`：五项导航、默认概览与页面选择；新增独立概览、运行监控、告警组件，不将全部请求逻辑堆入 App。
- `apps/platform-api/src/admin/`：新增监控查询与网关鉴权职责模块，复用已有授权入口；不改客户端本人监控接口。
- `scripts/monitoring-config.mjs`、`scripts/preprod-config.mjs`：认证代理、子路径、精确嵌入策略、应急链路及固定监控上游配置。
- `scripts/preprod.mjs`：镜像版本纳入管理端实际构建输入；新旧网关切换仍先暂停 API 并更新精确代理信任。
- 开发代理配置需支持同一公开 origin，未启用监控的日常开发仍可正常运行账号管理。

首版不计划新增业务 SQL 迁移：沿用平台角色与现有监控数据。若实现证明必须变更持久化结构，单独说明原因与迁移步骤，不直接修改业务库。

## 8. 验收门槛

1. 内网身份头伪造、浏览器伪造、绕过子路径、无会话、普通用户、仅 org_admin、suspended、banned、角色撤销全部有拒绝测试。
2. 三种有效平台角色均能只读查看；不能写看板、数据源、用户或告警规则；platform_admin 不自动拥有 Grafana 管理员权限。
3. 登录一次即可内嵌看板；退出、封禁、撤权后后续请求失效，无独立 Grafana token 绕过；所有两份 API 的判定一致。
4. 用实际固定 Grafana 镜像验证资源、跳转、时间范围、刷新和数据查询；不是仅检查 iframe 元素存在。
5. Prometheus 停止、Grafana 停止、查询超时、过期、空数据分别显示正确状态；不影响用户账号页与 Agent 页。
6. 平台 API/认证数据库不可用时，独立应急凭据仍能访问 Grafana；普通用户不能借此绕过访问控制。
7. 概览/告警不接收任意查询或目标地址，有超时、字节、数量和并发边界；查询错误不泄露凭据。
8. 桌面与 390px/320px 页面验收，导航、筛选、退出、乱序响应、iframe 移除与键盘访问正常。
9. 既有管理端、治理、平台隔离、预发配置与监控配置回归通过；只修改管理端文件也会改变网关镜像版本。
10. 常驻更新时保留卷、指标历史、证书和 Secret；比较更新前后状态，验证完整停机恢复，不关闭真实 Agent 能力围栏。

## 9. 执行顺序与完成口径

1. 复核本设计，完成后续逐任务实施计划。
2. 先做隔离的认证代理/子路径/应急入口可行性验证。
3. 以失败测试驱动权限和监控接口，再完成五项导航及页面。
4. 完成浏览器、故障降级与撤权验收，生成脱敏报告。
5. 准备常驻预发变更清单与回滚方案，经用户确认后部署；验收未通过不得标为已交付。

本轮仅形成设计文件，不启动新服务、不迁移数据库、不更改现有 Grafana、不提交或推送 Git。当前常驻预发继续运行旧版本。
