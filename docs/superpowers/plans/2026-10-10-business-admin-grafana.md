# 业务管理端 Grafana 完整接入与启动恢复

用户已授权开发及修复。沿用当前项目分支和已启动业务环境，不建立缺失私有配置的新工作树；不开放真实 Agent 或客户端部署/运维/审批功能。

## 设计与验收目标

- 当前 `http://localhost:5173/admin/` 使用原 Better Auth 会话和平台角色查看真实 Grafana，不要求预发账号。
- 保持五项导航。运行监控提供嵌入面板、独立打开、加载/不可用提示；概览和告警从业务 Prometheus读取。
- 独立业务 Prometheus、Grafana、私有 Caddy 桥接，归属标记、独立数据卷、固定版本、保留凭据与历史。仅桥接发布回环端口 9493，必须机器 Bearer；Grafana/Prometheus无宿主端口。原预发 8443/9443、卷、Secret 和账号不改。
- 业务 Prometheus采集本机 API 9465（专用 token）、Windows主机实际 CPU/内存及现有两个 Controller。业务 API预期副本1，不把预发2副本指标冒充业务数据。通过现有 Alertmanager接入告警，不新增账号或业务数据库迁移。
- 浏览器统一通过 `/api/admin/grafana/`。每次请求重新校验有效会话、active账号及显式监控权限，再由服务端注入固定Viewer身份；移除浏览器Authorization/Cookie/伪造身份头。只允许固定面板、静态资源、必要只读元数据和固定PromQL数据查询，不暴露自由代理或Grafana配置写入。原预发iframe保持兼容。
- Connector配置和机器凭据在已忽略output私有目录，显式由dev入口加载，生产默认不开启。无Docker socket/API增权。
- Controller因Docker启动期间共享overlay尚不可用导致的启动失败，先核对归属、持久网络和配置，再有限恢复；不重建ledger、Secret或业务数据。实际恢复后验收健康和原告警解除。
