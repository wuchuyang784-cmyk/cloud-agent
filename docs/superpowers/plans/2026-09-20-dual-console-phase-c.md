# 双端平台 C 批：服务器资源与调度观测

目标：不接模型、不开放 Agent 执行，在独立管理端展示真实主机 CPU/内存和 Swarm 容量、预留、限制、任务分配。

## 边界

- 沿用 Better Auth、显式平台角色与现有管理端，不新增认证体系。
- 独立只读采集进程定时写入最新快照，API 不访问 Docker，不逐请求采样。
- Windows 主机采样与 Docker Desktop Linux 节点容量分别展示；预留和限制不等于实测占用。
- 数据过期、未配置、采集失败、未采样分别表达，不补零。历史曲线留给既有 Prometheus/Grafana 方案。
- 初次开发不修改业务数据库；业务接入需用户明确授权、先备份后迁移。不自动安装主机服务、不操作常驻预发、不接真实 Agent。

## 实施顺序

1. 权限和数据契约测试先行。
2. 增加 035 迁移：强制 RLS、独立采集身份、快照上报/读取受限函数、管理访问审计。
3. 实现有界采集、快照校验、管理 API；MemoryStore 与 PostgreSQL 保持一致。
4. 新增管理端服务器资源页面，保持用户/Agent 页面与退出、撤权保护。
5. 独立数据库、后端与前端回归、构建、桌面/手机浏览器验收。
6. 中文操作文档列出人工迁移、采集账号配置和部署验收的剩余步骤。

## 验收重点

- 普通用户不能读基础设施；撤销平台角色后立即拒绝；应用账号不能上报。
- 采集账号仅能更新 DBA 绑定的源，不能读取用户/管理数据，旧采样不能覆盖新快照。
- 缺失、不合法、过期数据不会显示成健康或零占用；响应不含 Docker 环境变量、内部地址、凭据。
- Swarm 预留按实际非终态任务计算，包括滚动更新中的旧任务；无节点任务单列等待分配。
- 业务 `.env` 与真实数据库不进入自动化验收。
