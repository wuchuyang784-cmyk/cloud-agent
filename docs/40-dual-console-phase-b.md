# 双端平台 B 批：客户端本人 Agent 监控

日期：2026-09-19。代码与独立环境验收完成；未对业务库或常驻预发执行部署。本批不代表真实 Runtime 监控、服务器运维或账号封禁已完成。

## 1. 本批交付

客户端入口：**开发与部署 → 可观测**。保留原导航和资源库，只替换原来的可观测占位页。

- 本人 Agent 列表、名称/ID 搜索、每页 20 条的游标分页。
- 单个 Agent 的登记状态、引擎、登记更新时间和路由记录时间。
- 今日、近 7 天、近 30 天的已记录调用、Token、失败及延迟样本统计，按上海自然日展示历史。
- 刷新、无 Agent、搜索无结果、无样本、读取错误、404、超时和会话过期状态。
- 不展示其他用户、服务器、容器、数据库连接、管理操作或 Grafana 管理入口。

本批沿用 `apps/saas推荐.md` 的能力分工：Better Auth 提供凭据与会话，平台通过 Principal、业务所有权和 PostgreSQL RLS 决定数据范围。Open SaaS 的客户端/管理端分离思路继续沿用，但不迁移到另一套 SaaS 框架或用户模型。

## 2. 数据不是实时健康指标

| 页面内容 | 来源及含义 |
| --- | --- |
| 登记状态 | `agents.status`，数据库中的历史记录；`ready` 不能证明现在在线 |
| 路由记录 | `runtime_routes.last_seen_at`，现有生命周期写入的时间，不是持续心跳 |
| 记录陈旧 | 路由记录距服务端读取时间超过 5 分钟；未来时间显示异常，缺失显示无路由记录 |
| 实时采样、CPU、内存 | 尚无可信采样链路，接口返回 null，界面显示未接入/未采集 |
| 调用、Token、失败 | 当前 Agent、当前用户、当前组织、选定时间范围内的 `usage_events` |
| 延迟均值 | 仅对非空 `latency_ms` 记录求均值，同时显示样本数；不是每次调用都有样本 |
| 历史用量 | 只返回有记录的日期，不把缺失日期补成零 |

无事件时调用、Token、失败和平均延迟为 null，事件数和延迟样本数为 0。记录数值超出 JavaScript 安全整数范围时相关指标返回 null，避免展示失真数字。历史用量可能来自 mock；现有 legacy 写入也没有覆盖所有失败，因此本批**不计算整体成功率、可用率、计费金额或资源占用估计值**。

所有统计窗口使用 `Asia/Shanghai`：近 7 天包含今天和之前 6 个自然日，近 30 天同理；截止服务端读取时刻，不纳入未来事件。`lastRecordedAt` 取选定范围内最大的 `occurred_at`，代表最近事件时间，不是采集心跳或数据库提交时间。

前端每 30 秒更新本页记录的新旧提示，不自动轮询后端。查看新数据需要点击刷新；页面快照超过 5 分钟显示过期提示。

## 3. 接口及权限

```text
GET /api/user/monitoring/agents?limit=20&after=agent-id&q=名称
GET /api/user/monitoring/agents/agent-id?range=today
```

- 列表 `limit` 范围 1..50；`after` 为上一页 `nextCursor`，`q` 最长 100 字符。
- 明细 `range` 只接受 `today`、`7d`、`30d`，默认今日。
- 组织和用户只来自服务端 Principal。即使登录人有平台管理角色，也只能通过这两个客户端接口看自己的 Agent。
- 不接受前端指定 owner、user、organization；未知参数、重复参数、非法分页或时间范围返回 422。跨用户、跨组织和不存在均返回 404，写方法返回 405。
- PostgreSQL 使用本人 scope 事务；列表、明细同时显式核对 `organization_id` 和 `owner_user_id`。事件聚合额外核对 `user_id`、`organization_id`、`agent_id`。
- 固定响应字段，不返回内部 Runtime URL、主机配置、用量 metadata、对话、凭据或身份 subject。所有监控响应及认证失败使用 `Cache-Control: no-store`。
- 数据库语句限时 3 秒，异常统一返回 503 `monitoring_unavailable`。日志只记录固定事件，不记录查询词、原始 SQL 或错误对象；指标路由归一化，不能包含 Agent ID。
- 前端请求超过 15 秒显示可重试错误；新查询、退出、卸载会清空旧数据并取消请求，旧响应不能重新写回。

列表不做全量总数查询，统计最多聚合 30 天；复用既有用户/Agent 时间索引。当前验证覆盖隔离、双 API 和连接池复用，**不等同于大数据量容量验收**。公网前仍需压测、请求限流、保留周期及可能的预聚合设计。

## 4. 在你的开发环境使用

B 批读取已有表，没有新增 SQL 迁移，不需要导入测试数据。若当前 API 是修改代码前启动的，需要你在其终端 Ctrl+C 后重启，以加载新路由：

```powershell
conda activate cloud
Set-Location E:\cloud-agent
npm run dev
```

打开启动脚本打印的客户端地址，默认 `http://127.0.0.1:5173/`；使用自己的邮箱账号登录，进入“开发与部署 → 可观测”。原来没有 Agent 的账号显示“暂无 Agent 记录”是正常情况，不应为展示监控而重新开放平台模式的 Agent 创建与执行。

本次浏览器验收使用一次性 PostgreSQL、真实 Better Auth 和合成历史记录，不连接 `bairui`，不读取业务 `.env`，不重启现有开发服务或常驻预发。截图在 `output/playwright/client-monitoring/`。这些测试账号不是你的真实管理员。

## 5. 管理员账号接入进展

用户随后明确指定了已注册的登录邮箱。2026-09-19 已对该唯一账号增加 `platform_admin` 权限，并将显示名称设为 `admin`；仍使用原邮箱与原密码登录，不另建重复身份，不迁移或删除个人空间及客户端数据。

已先备份业务库 `bairui`，再导入 034、授予受限应用账号最小函数权限并记录授权审计。真实应用数据库连接验证通过，其他 4 个账号无管理权限；原密码未读取、重置或输出。详细操作与备份验证边界见 `docs/39-dual-console-phase-a.md` 第 8 节。用户仍需重启旧开发服务后完成真实账号的浏览器登录验收；常驻预发未修改。

后续密码仅保存在本机不入版本库的交付文件中，不写入源码、测试、文档、日志或聊天；认证数据库只保存 Better Auth 管理的密码哈希。不要发送数据库连接串、现有密码或密钥。
