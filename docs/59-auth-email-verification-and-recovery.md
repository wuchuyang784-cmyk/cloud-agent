# 邮箱验证与密码找回

功能默认关闭。保持 Better Auth 1.7.5、原认证身份、账号治理与个人空间；不自动给老账号标记已验证，不按邮箱关联历史身份。

## 配置和切换

| 变量 | 值 |
| --- | --- |
| `BAIRUI_AUTH_EMAIL_MODE` | `off`（默认）、`transition`（老账号验证、暂停注册）、`enforce`（新旧账号统一强制验证、恢复注册） |
| `BAIRUI_AUTH_MAIL_FROM` | Resend 已验证发件域下的单个邮箱，不含显示名 |
| `BAIRUI_AUTH_MAIL_SECRET_FILE` | API 容器内可读的绝对 Secret 文件路径，例如 `/run/secrets/auth-mail-key`；文件只有 API Key，可带一个换行 |
| `BETTER_AUTH_URL` | 客户端实际访问的固定同源地址；生产为 HTTPS |

启用前备份目标数据库，按序执行 047（依赖 032、036）。现有受限认证应用角色需对新表 `ba_email_challenge` 有 SELECT、INSERT、UPDATE，保留原认证和账号治理函数权限。不要授予 PUBLIC。对于已有常驻预发，不改安装标记或自动迁移旧卷。先在独立预发确认迁移、HTTPS 回调页面、受限角色和真实测试邮箱收信，再安排常驻环境变更。生产 Secret 不放进 Git、命令行参数、浏览器或共享会话。

首次只统一启用 `transition`：老用户正常登录并在个人设置验证邮箱，暂时停止新注册。确认至少一名有效平台管理员已验证、能重新登录后，才把所有 API 副本切到 `enforce`。切换使用维护窗口或先停止旧副本接受请求，不允许混跑旧认证门禁；源代码升级不等于运行中副本已切换。强制后如果发信异常，保留强制和已验证账号登录，修复邮件配置，不退回允许未验证会话的模式。

## 行为与故障处理

- 验证链接有效 24 小时，找回链接有效 30 分钟；每账号每用途发送间隔至少 60 秒，重发使此前链接失效。链接先打开客户端确认页，预读不验证也不重置。强制期重新提交正确密码可触发受限的验证重发。注册时已存在邮箱不重发，也不自动进入控制台。
- 个人设置只为当前有效会话申请验证邮件；浏览器额外传入显示中的用户 ID 做一致性检查。若另一标签页切换了登录账号，返回 409，既不发信也不按客户端提供的 ID 选择收件人。
- 找回申请不披露账号是否存在或是否可用。只有已验证、未封禁且有密码凭据的账号会收到邮件。找回不恢复账号治理状态。未验证且忘记原密码的历史账号必须人工核验，不能通过邮箱找回接管。
- PostgreSQL 存令牌摘要；密码写入、令牌消费和撤销全部旧会话同事务提交。邮箱验证也撤销该身份的验证前会话，避免切换强制模式后旧 Cookie 恢复权限。启用时，登录先通过跨副本原子限流（同来源 10 秒 3 次），再在同一身份锁内校验密码并写入会话；确认后需重新登录。
- 发信队列按进程有限，交付失败或重启可能丢弃待发任务。确认页面不承诺送达。查看固定日志事件 `auth_email_delivery_failed`、`auth_email_queue_full` 和认证请求状态；记录不含邮箱、令牌、密钥、链接或供应商响应。发送异常时可按冷却时间重新申请；不关闭认证限流。

## 本地验证

在 Conda `cloud` 下运行：

```powershell
npm run test:auth-email
npm run test:auth-email:db
npm run test:auth-email:web
```

专项使用临时数据库和测试发信器，不读业务环境。数据库默认使用本机 Docker；也可显式将 `BAIRUI_AUTH_EMAIL_TEST_PG_BIN` 设为已安装 PostgreSQL 的绝对 `bin` 目录，只启动临时回环实例。浏览器专项使用已安装的 `BAIRUI_PLAYWRIGHT_MODULE`，可通过 `BAIRUI_BROWSER_EXECUTABLE` 指定 Chromium。

真实投递需另行通过独立预发和获授权的测试邮箱验收；测试适配器通过不代表 Resend 真实送达。

2026-11-12 本地验收：一次性 PostgreSQL 17.11、独立 API 连接池和 Chromium 联调 9 项全部通过；后端全量 604 通过、20 跳过（隔离环境专项）、0 失败，客户端 50 项和管理端 36 项通过，双端生产构建通过。覆盖旧会话不复活、同来源与 IPv6 /64 跨副本限流、旧标签页错账号拒绝、并发重置、撤销故障回滚以及真实页面流程。没有发真实邮件或修改部署。
