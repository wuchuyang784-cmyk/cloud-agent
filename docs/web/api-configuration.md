# API 配置页设计说明

## 目标与范围

API 配置是当前已登录用户的模型连接池，而不是某个 Agent 的配置子页。用户可维护多个 Provider、API Key 与自定义 Base URL；后续 Agent 创建或编辑时只选择已验证连接及其模型，不重复填写密钥。

本 MVP 只实现前端交互和 mock 数据，不请求或持久化真实凭据。

## 页面结构

- 顶部：面包屑、页面说明和唯一主操作“新增连接”。
- 安全提示：明确 API Key 不写入 React state、URL 或浏览器存储。
- 左侧：紧凑连接列表，展示 Provider、名称和状态点，用于快速切换。
- 右侧：所选连接的状态、Base URL、掩码 Key、最近验证时间、调用量和可用模型。
- 底部：验证、启用或停用操作。停用连接后 Agent 不应再可选用它。

## 状态模型

| 状态 | 含义 | 可用性 |
| --- | --- | --- |
| 已验证 | 认证与模型探测成功 | 可被 Agent 选择 |
| 待验证 | 新建或重试验证已提交 | 不可用于生产调用 |
| 已停用 | 用户主动停止该连接 | 不可选择，重新启用后待验证 |

提交新增连接时，表单只将非敏感元数据写入 mock 状态；API Key 输入仅作为本次表单提交的必填校验项。

## 视觉与响应式

页面沿用 `platform-overview(优化版).html` 的浅背景、细边框、6-8px 圆角和低阴影。连接列表与详情共享一个工作区边框，避免堆叠大卡片。状态均同时使用 Lucide 图标或文字，不能只依赖颜色。

桌面采用 270px 连接列表加详情面板；小于 600px 时连接列表变为三列快捷选择，详情纵向排列，属性改为单列，保证无水平溢出。
