# 会话管理页设计说明

## 页面定位

会话管理首页是当前用户下的 **Agent 会话概览列表**，按 Agent 汇总其用户对话会话；定时任务、API 调用和其他非对话运行记录仍属于“可观测”。点击一个 Agent 后，进入独立的“Agent 会话详情页”，在该页查看此 Agent 下的具体会话与消息记录。

从左侧导航进入时，展示全部 Agent 的会话汇总。从“智能体 Agents / 我的项目”中的会话管理按钮进入时，直接进入对应 Agent 的会话详情页，继承当前会话管理时间范围（首次默认“今日”）；用户可以返回会话管理首页。

## 页面结构

- 顶部：面包屑、标题和统一的时间范围控件（今日、近 7 天、近 30 天）。
- 首页筛选栏：关键词、Agent 运行状态和时间范围。关键词匹配 Agent 名称与 ID；单会话状态筛选仅在 Agent 会话详情页提供。
- Agent 会话概览列表：Agent 名称、运行状态、会话总数、进行中会话数、近 24 小时消息数、最新活跃时间、异常会话数；点击整行进入 Agent 会话详情页。
- Agent 会话详情页：顶部展示名称、运行状态、所选范围内的会话总数、进行中数、消息数、异常数、最新活跃时间及“返回会话管理”入口；下方提供该 Agent 的会话筛选栏与会话列表。它不重复 Agent 配置、模型或渠道配置；点击会话进入独立的单会话详情页，不与列表并排。
- 会话列表：会话标题或首句、最后活跃时间、消息数、状态（进行中、已结束、异常）。
- 会话详情：完整消息流、会话元数据与工具调用摘要。

会话列表默认按最后活跃时间倒序，每页 20 条并提供分页。筛选条件变更时回到第一页；MVP 使用本地 fixture 保持与后端查询参数一致的语义。首页时间范围影响所有 Agent 聚合指标；进入 Agent 会话详情页后保留该范围，仅显示范围内有活跃记录的会话。面包屑路径为“会话管理 / Agent 名称 / 会话标题”，每一层都可返回上一页。

消息流显示用户、Agent、系统或工具角色及精确时间。工具调用默认收起，摘要显示工具名称、结果状态与耗时；展开后查看本地 fixture 中的请求和结果内容。

会话元数据包括会话 ID、所属 Agent、渠道、开始时间、最后活跃时间、累计消息数、累计 Token、总耗时和状态。渠道仅描述来源类型，不记录或展示终端用户身份。

## 详情操作与状态

提供复制会话 ID、导出记录和结束会话。结束会话仅对“进行中”状态可用；MVP 仅更新本地 mock 数据。页面不提供删除记录，避免与后续审计留存规则冲突。

异常会话额外展示异常摘要与最近失败步骤，并提供“进入 Agent 配置”入口；不提供重试，因为会话重试依赖后端任务及幂等语义。

当前 MVP 尚未提供独立的 Agent 配置页，“进入 Agent 配置”先跳转到“智能体 Agents / 我的项目”并定位、高亮对应卡片；独立配置页完成后替换为其详情入口。

## 视觉约束

遵循 `apps/console-mvp/DESIGN.md` 和 `docs/platform-overview(优化版).html`：浅灰画布、白色细边框工作区、6 至 8px 圆角、高密度业务信息。首页汇总列表、Agent 会话详情与单会话详情是独立页面层级，避免双栏并排和卡片嵌套。图标统一使用 Lucide Icons；状态必须同时具有图标或文字，不能只依赖颜色。
