# 部署发布页设计说明

## 页面定位

部署发布服务于当前普通用户的单用户控制台，只展示和管理本人智能体的发布记录与发布状态。它不暴露服务器、备份、回滚、控制命令或平台级发布能力。

## Git 自动部署

当前 MVP 仅支持 GitHub。用户在 Agent 配置页绑定 GitHub 仓库和默认部署分支，例如 `main`。向该分支推送代码后，平台创建发布记录，按“构建中 → 校验中 → 发布中 → 已发布或失败”流转。GitLab、Gitee 等 Provider 不在本期 UI 中预留入口。

当自动发布关闭时，推送会创建“待发布”记录；用户在部署发布页显式确认后再进入构建流程。普通用户不在页面手动创建无来源发布，只能确认已存在的待发布记录、重试失败记录，或重新部署已发布记录。所有操作均基于原提交 SHA 与配置版本生成新记录，不修改历史记录。当前纯前端 MVP 只使用 mock 元数据表达授权、仓库和 Webhook 状态，不写入浏览器存储。

| 当前状态 | 用户可执行操作 | 新记录状态 |
| --- | --- | --- |
| 待发布 | 确认发布 | 构建中 |
| 失败 | 重新触发构建 | 构建中 |
| 已发布 | 重新部署 | 构建中 |

新建 Agent 在第 4 步保存时同时创建 Agent 与配置版本：开启自动发布时立即生成“构建中”的首次发布记录；关闭时生成“待发布”记录，由用户在部署发布页确认发布。后续 Git 推送沿用同一发布语义。

## 部署发布页

- 顶部：时间范围、Agent 筛选和“查看 Agent 配置”入口。
- 发布记录：按最新触发时间倒序，支持 Agent、发布状态和时间范围筛选；展示 Agent 名称、提交 SHA、触发方式、触发时间、配置版本、发布状态、耗时与失败摘要。
- 点击一条记录进入独立详情页，不在列表内展开。
- 记录详情：展示状态时间线与构建、校验、发布的 mock 摘要；失败时展示脱敏失败摘要，提供“查看 Agent 配置”和“重新触发构建”。重新触发会基于同一提交 SHA 与配置版本生成新记录，不修改旧记录。
- 待发布记录：提供唯一主操作“确认发布”；点击后仅更新本地 mock 状态。

## Agent 配置页

路径为“智能体管理 → Agent 卡片 / 配置 → Agent 配置详情”。新建与编辑共用四步：基础信息（名称、描述、开发框架）、模型与工具（已验证模型连接、模型、工具能力）、渠道接入（Web、飞书、微信、API 等）、代码与发布（GitHub 仓库、部署分支、自动发布开关、配置确认）。保存配置后生成新的配置版本并标记为待发布。

## 视觉与权限

遵循 `apps/console-mvp/DESIGN.md` 和 `docs/platform-overview(优化版).html` 的紧凑业务控制台视觉。所有图标使用 Lucide Icons。当前用户只可配置和查看自己的 Agent；不提供用户侧回滚。真正的 GitHub 授权、Webhook Secret、构建凭据和控制平面命令都由服务端安全管理。
